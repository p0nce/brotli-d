Brotli encoder: remaining work
==============================

State (2026-10-21)
------------------
Milestones 1-6 of the plan are done: bit writer, prefix codes, greedy/lazy
matching, literal and distance context modeling, static dictionary, block
splitting, NPOSTFIX/NDIRECT search, optimal parsing (levels 10-11).

Level 11 vs the reference encoder at q11 (smaller is better):
    text -0.35%, C source +0.05%, maps -0.01%, qoi images -0.61%, 5 KB text +0.71%
Level 10 beats q10 everywhere. Level 6 beats q6 except on large text (+0.9%).

Verified: all levels round-trip through the D decoder and Google's C decoder
on the edge-case corpus (encode_test.py). The full suite (all windows,
18 MB inputs) passed up to milestone 5. The decoder suite still passes.

2. Speed pass
-------------
Rules:
- Keep a speed change if it gains at least this much speed per +1% of size
  (speedups that don't lose size always qualify):
    levels 0-3: 5%    levels 4-6: 15%    levels 7-9: 50%    level 10: 200%
    level 11: 1000%, or a major simplification of the encoder.
- One speed change per commit, measured on its own: each can be tuned or
  reverted separately.
- Tuning constants are marked @tuning (UDA). The last pass tunes each of
  them, one by one.

Profile first, per phase, on: text, C source, maps, qoi, 5 KB, 50 bytes.
Targets: level 6 at the speed of q6 or better, level 11 >= 1 MB/s.

[ ] Fixed per-call costs (small inputs): workspace allocations, clearing
    of 256 KB histograms, 64 KB context histograms per mode, hash table
    clearing. Size everything from the input length.
[ ] Clustering: the (block type x 64 contexts) literal histograms are the
    main cost at levels 5-9. Options: cluster each block type's contexts,
    then merge across types; cheaper pair costs; fewer literal block types
    at mid levels; skip clustering for blocks with few literals.
[ ] Block splitter: fewer histograms/iterations at mid levels; sample the
    data for the initial histograms; float vs double costs.
[ ] Match finder hot loop (levels 0-9): @trusted pointer code for the
    candidate loop and quick rejects, without bounds checks where proven
    safe. Check what LDC does with load32/load64.
[ ] Bit writer: 64-bit flushes, fewer branches.
[ ] Levels 0-1: a dedicated single-pass compressor (one hash entry, no
    lazy matching, static-ish codes, no context modeling), like the
    reference's q0/q1. Goal: 150+ MB/s.
[ ] Optimal parsing: the trial meta-block encodes at level 11 (one per
    pass); cheaper cost model updates; ComputeMinimumCopyLength-style
    pruning for the tree matches too; profile zopfliShortestPath.
[ ] Tune levels 2-9 for a smooth speed/ratio curve (bench at each level).
After each change: unit tests, quick suite, ratio unchanged unless intended.
